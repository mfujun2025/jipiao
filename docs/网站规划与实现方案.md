## 一、项目概述

### 1.1 一句话概括

机票.CC 是一个**中文机票资讯网站**：围绕「机票价格动态、航线资讯、出行攻略、航司动态、优惠活动」五大板块组织内容，帮助普通出行者在**下单前把决策做对**——而不是替他们下单。

### 1.2 为什么这个站值得做（市场判断）

中文机票信息市场呈「**交易垄断、内容分散**」格局：

- **交易层被 OTA 占据**：携程、去哪儿、飞猪、同程、美团、智行构成第一梯队，用户「搜价—比价—下单」主链路已被闭环锁定。
- **内容层高度碎片化**：用户做决策前研究时会流向右小红书、知乎、马蜂窝、本地宝等，但内容碎片化、可信度参差、无结构化沉淀。
- **关键洞察**：机票内容需求本质是「**决策焦虑**」需求。用户不缺一个出票按钮，缺的是一个**中立、可核对、说得清为什么**的信息源。这恰是 OTA 因利益冲突而不愿做、也不适合做的部分。

### 1.3 可行性边界（不吹）

- 站点**不产生交易收入**，变现依赖内容影响力 + 邮件订阅资产 + 未来合规标注的合作。
- 机票价格属**高频变动信息**，内容保鲜成本高，必须建立复核机制（见第六章）。
- 中文域名存在结构性风险（见第二章 2.3），需配套应对方案。

## 二、核心定位与域名策略

### 2.1 定位陈述

> **机票.CC —— 不卖票的机票信息站：把「机票什么时候买、怎么买才不亏」这件事，用可核对的数据和中立的态度讲清楚。**

对外候选 slogan：

> 查价格规律、看航线真相、避购票的坑 —— 我们不帮你下单，只帮你做对决定。

### 2.2 三个差异化支点（为什么用户不去携程而来这里）

| 支点 | 具体含义 | 为什么 OTA 做不到 |
|---|---|---|
| **① 中立性红利** | 站内不卖票、无下单闭环，因此可以客观横评、曝光价格陷阱、讲清退改风险 | OTA 内容天然为自家交易服务，中立横评与其商业模式直接冲突 |
| **② 结构化数据沉淀** | 价格动态表、会员日日历、燃油与机建费标准、行李额度对比等**可复用表格页**，长期维护形成数据护城河 | OTA 看重交易转化，不愿为「不直接带来下单」的琐事投入长期编辑 |
| **③ 出行决策陪伴** | 从「想买票」到「顺利登机」的全链路信息，用**旅客语言**而非行业术语讲 | 航司媒体太专业、OTA 太商业，中间「懂行的朋友」这一角色缺位 |

### 2.3 中文域名「机票.CC」的客观评估（不粉饰）

中文域名是一把**双刃剑**，必须清醒认知：

**利：**

| 维度 | 说明 |
|---|---|
| 品牌记忆成本低 | 对中文用户「机票.CC」读得出、记得住，线下口播与口碑传播友好 |
| 锚文本天然含词 | 外链锚文本「机票.CC」本身即「机票 + 品牌」组合，比拼音串更易形成相关性联想 |
| 搜索结果展示友好 | 搜索结果直接显示中文，点击意愿通常高于拼音串，间接提升 CTR（正向行为信号） |
| 品牌保护价值 | 抢占直观入口，防止被抢注干扰品牌形象 |

**弊（务必正视）：**

| 维度 | 说明 | 应对措施 |
|---|---|---|
| **无排名加权** | 主流搜索引擎**不因域名是中文而给予收录或排名优先**，权重仍取决于内容质量、外链与站点结构 | 不把域名当 SEO 优势，把资源投在内容与结构上 |
| **「机票」是通用词而非独占品牌词** | punycode `xn--yetu496a.cc`，「机票」为行业通用词，无法作为独占商标式品牌词保护；他人可用「机票.中国」「机票.com」等分流品牌搜索 | **建议同步注册并 301 到主域的拼音域名**（如 `jipiao.cc`）作为防御与直达入口 |
| **输入成本与截获** | 用户需切换中文输入法；地址栏输入「机票.CC」时常被搜索框截获、跳转搜索而非直达 | 在页脚、名片、内容中同时给出 punycode 与拼音域名；推广物料以可点击链接为主 |

**结论**：中文域名作为**品牌资产**值得用，但**不能当作 SEO 杠杆**。SEO 的全部收益必须来自内容体系与站点结构本身——这也正是本方案的设计前提。

## 三、目标用户群体

### 3.1 核心用户画像

| 画像 | 特征 | 典型需求 | 对应栏目 |
|---|---|---|---|
| **A. 预算敏感的自由行旅客**（主力，约 45%） | 25-35 岁，一年飞 2-4 次，价格敏感但不极端 | 「现在买还是再等等」「怎么买不亏」 | 价格动态 · 出行攻略 · 优惠活动 |
| **B. 高频商务出行者**（约 20%） | 28-45 岁，一年飞 6 次以上，时间价值高于价格 | 班次密度、时刻衔接、中转效率、退改灵活度 | 航线资讯 · 航司动态 |
| **C. 家庭 / 亲子出行者**（约 20%） | 30-45 岁，带孩子或老人，怕出错 | 婴儿票儿童票规则、行李额度、机场流程 | 出行攻略 · 航司动态 |
| **D. 首次乘机 / 低频旅客**（约 15%） | 学生、首次出国、下沉市场 | 「第一次坐飞机流程」「证件和行李怎么准备」 | 出行攻略（新手向） |

### 3.2 用户的核心痛点（内容选题的根）

1. **怕买贵** —— 不知道该什么时候下单，缺少价格参照。
2. **怕踩坑** —— 低价票的退改与行李限制看不懂，实际总花费超预期。
3. **怕出错** —— 中转衔接、证件、值机流程不确定，担心误机。
4. **不信平台** —— 觉得 OTA 的「最低价」不可信，需要第三方视角。

> 四个痛点的共同点：**用户要的是「判断依据」，不是「一个价格」**。这决定了本站的内容形态必须以「方法 + 数据 + 口径」为核心，而不是搬运报价。

## 八、技术实现方案

### 8.1 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 站点形态 | 纯静态 HTML + CSS + 原生 JS | 无构建依赖、加载极快、SEO 友好、托管成本近零 |
| 生成方式 | Python 静态生成器 `build.py` | 单一数据源避免多页不一致，改数据即全站同步 |
| 样式 | 手写 CSS 设计系统（CSS 变量） | 无框架体积负担，便于长期维护与主题调整 |
| 交互 | 原生 JS（IIFE，无依赖） | 首屏无阻塞、无第三方脚本风险 |
| 数据 | `data.js`（由 `build.py` 生成） | HTML 静态渲染（利于 SEO）+ JS 数据层（利于交互）双轨 |

**关键设计取舍**：列表内容**同时**静态渲染进 HTML 并由 JS 数据层驱动交互。这样搜索引擎抓取到的是完整内容，用户又能享受筛选、排序与站内搜索——避免了「纯前端渲染导致内容不被收录」的常见问题。

### 8.2 已实现的交互能力

| 能力 | 实现方式 |
|---|---|
| 站内搜索 | 前端索引 `SEARCH_INDEX` 即时过滤，支持 `?q=` 直接带入 |
| 栏目筛选 | `data-filter` 属性 + `data-cat` 匹配，即时显隐 |
| 价格表排序 | 表头点击按「最低价 / 均价 / 环比」升序降序排列 |
| FAQ 折叠 | `aria-expanded` + CSS 状态类，无障碍友好 |
| 邮件订阅 | 邮箱格式校验 → 生成 mailto → 唤起客户端 → 轻提示 |
| 复制邮箱 | `navigator.clipboard` + `execCommand` 降级方案 |
| 移动端导航 | 汉堡菜单，点击导航项自动收起 |
| 价格播报 | 纯 CSS 动画滚动，悬停暂停 |
